# Фаза 5 — hardening и деплой

Ты реализуешь **Фазу 5** проекта **LLM Second Brain** — self-hosted MCP-сервера долговременной памяти для LLM (харнес Open WebUI).

## 1. Документация (источник истины)

Файлы в `/home/user/projects/llm-second-brain/`:
- `REQUIREMENTS.md` (v0.6) — NFR-1…NFR-6, конфигурация (§8), риски (§9).
- `ARCHITECTURE.md` (v0.5) — BackupService (§3.2), безопасность (§6), тестирование (§7).
- `README.md` — обзор.

Прочитай все три полностью, прежде чем писать код.

## 2. Контекст (что уже сделано)

Фазы 1–4 завершены: каркас + хранилище + векторизация/поиск/дедуп + фоновая суммаризация. Функционально сервис готов — осталось hardening и деплой.

## 3. Задача Фазы 5

1. **Лимиты** (NFR-6) — все ограничения env-переопределяемы и валидируются.
2. **Логирование** (NFR-4) — stdout JSON, `LOG_LEVEL`; вызовы инструментов с латентностью и числом результатов; тексты запросов — первые 80 символов; содержимое заметок в логи НЕ пишется.
3. **Backup** — `BackupService`: периодический снапшот БД через SQLite `backup` API (онлайн, без остановки) в `BACKUP_DIR`=`/data/backups`, ротация по `BACKUP_KEEP`=7, интервал `BACKUP_INTERVAL_SEC`=86400.
4. **README** — полная инструкция подключения Open WebUI (внешний MCP в админке, Bearer-токен, env).
5. **Деплой** — сборка образа, подъём на целевом сервере (compose, `restart: unless-stopped`, non-root, volume `/data`).

## 4. Ключевые параметры

`BACKUP_DIR`=/data/backups, `BACKUP_INTERVAL_SEC`=86400, `BACKUP_KEEP`=7, `LOG_LEVEL`=INFO, `PORT`=8080.

## 5. Критерии приёмки

- Логи JSON, без утечки содержимого заметок.
- Backup работает (снапшоты + ротация).
- README полный и проверенный.
- Образ собирается, сервис поднимается на целевом сервере, `/health` зелёный.

## 6. Вне скоупа Фазы 5

Function-фильтр Open WebUI — Фаза 6 (опционально).

## 7. Ритм работы

Один шаг → тесты → отчёт → жди «дальше». Не делай всю фазу одним махом.
